# DSHD SPK Package (0.2.0, not verified on real DSM hardware)

This is the main implementation of the "SPK shell + Docker runtime", corresponding to route D in the research document:

- `INFO`: DSM 7.2+, `x86_64`/`armv8`, `startable=yes`, `ctl_stop=yes`;
- `conf/privilege`: `package` by default; only `postinst`/`preuninst`/`start`/`stop`/
  `status` run as root (required by the Docker socket; see
  [../docs/spk.md](../docs/spk.md#3-privilege-model) for details);
- `conf/resource`: registers 3080/tcp via `port_conf/dshd.sc`;
- `scripts/start-stop-status`: locates Docker/Compose, creates the data directory, runs `compose up -d`,
  polls the logs, writes token/status; `stop` runs `down`; `status` checks the container;
- `scripts/token`: prints the first-start token URL;
- `scripts/installer` + `postinst`/`preuninst`: initialize config/directories; on uninstall only runtime state is cleared;
- `package/docker-compose.yml`: parameterized image tag, port, data paths, public URL;
- `package/config.env.example`: runtime configuration template;
- `PACKAGE_ICON.PNG` / `PACKAGE_ICON_256.PNG`: generated by `tools/gen-icons.py`;
- `build-spk.sh`: produces a plain tar SPK (DSM 7 does not require GPG), with integrity checks.

## Build and checks

```bash
./spk/build-spk.sh
# dist/dshd-0.2.0.spk

../scripts/check-spk.sh
# or from the repo root: scripts/check-spk.sh
```

The build script validates the required INFO keys, icon sizes, JSON, `.sc`, script syntax, and required files; a missing file
fails the build immediately.

Regenerate the icons:

```bash
make icons
# or python3 spk/tools/gen-icons.py
```

## After installation

```bash
sudo vi /var/packages/dshd/var/config.env
sudo synopkg start dshd
sudo /var/packages/dshd/scripts/token    # or sudo dshd-token
cat /var/packages/dshd/var/status
```

- `DSHD_IMAGE` must already exist locally on the NAS (check with `docker image inspect`); the package does not pull automatically;
- `DSH_PUBLIC_URL` / `DSH_TRUSTED_HOST` must match the reverse proxy domain;
- Token file `/var/packages/dshd/var/token-url.txt`, 0600 root;
- If the token is missing, start returns failure and the container is kept for diagnostics;
- Data: `/volume1/docker/dshd` and `/volume1/dshd-workspace` (configurable).

## Permission trade-offs

The Docker socket is owned by root. Adding the package user to the `docker` group is equivalent to persistent root privileges; this package instead elevates only the 5 control scripts and has `start-stop-status` parse `config.env` in a whitelisted manner
(no source, no eval), reducing configuration injection risk. The `docker-project` variant can avoid the Docker
CLI, but is still experimental.

## Reverse proxy

Recommended: DSM Control Panel → Login Portal → Advanced → Reverse Proxy, destination
`http://127.0.0.1:3080`, with WebSocket enabled. `conf/resource.webservice.example.json`
is a Web Service worker candidate, **not enabled and not verified**; do not merge it directly into
`conf/resource` unless WebStation dependencies, the alias portal domain, and the Host header are confirmed on real hardware.

## Not verified

SPK install/upgrade/uninstall, `ctrl-script` root, Container Manager's Docker/Compose
paths and arguments, port registration UI, reverse proxy TLS/WebSocket, token log format, ACL/UID, icon display,
`/usr/local/bin` link strategy. **Do not ship as a release package before real-device verification.** For the full checklist, see
[../docs/spk.md](../docs/spk.md#9-unverified-checklist).
